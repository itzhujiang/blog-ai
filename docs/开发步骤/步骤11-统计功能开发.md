## 一、步骤目标

实现文章阅读量统计和阅读时间展示功能。采用 CSR（客户端渲染）策略，在页面加载后通过 API 实时获取和更新统计数据，与 ISR 缓存的静态内容分离。具体包括：

1. 创建统计 API 接口（获取统计数据 + 记录阅读量）
2. 创建客户端统计组件，在文章详情页和文章列表页实时展示阅读量和阅读时间
3. 文章详情页访问时自动递增阅读量

---

## 二、需求说明

### 2.1 功能要求

- 文章详情页展示阅读量（viewCount）和预计阅读时间（readingTime）
- 文章列表页的文章卡片展示阅读量
- 用户访问文章详情页时，自动递增该文章的阅读量
- 统计数据通过 CSR 实时获取，不影响 ISR 缓存
- 阅读量和阅读时间数据来自数据库 `articles` 表的 `view_count` 和 `reading_time` 字段

### 2.2 UI 设计要求

- **文章详情页 ArticleHeader 元信息区域**：
  - 在现有元信息行（日期、作者、分类、评论数）中新增：
  - 阅读量：`visibility` 图标 + `{viewCount} 阅读`
  - 阅读时间：`schedule` 图标 + `{readingTime} 分钟阅读`
  - 统计数据加载前显示占位符（`--`），加载后替换为实际数值
  - 使用 Material Symbols 图标，与现有元信息风格一致

- **文章列表页 ArticleCard 底部区域**：
  - 在现有评论数旁新增阅读量：`visibility` 图标 + `{viewCount} 阅读`
  - 统计数据加载前显示占位符（`--`），加载后替换为实际数值

- **搜索结果页 SearchResultCard 底部区域**：
  - 与 ArticleCard 保持一致，新增阅读量展示

### 2.3 业务规则

- 阅读量递增规则：每次访问文章详情页时递增 1（简单计数，不做去重）
- 阅读时间来源：数据库 `reading_time` 字段（由内容管理系统在发布时计算并写入）
- 统计数据通过独立 API 获取，不与文章内容 API 耦合
- 统计 API 响应头设置 `Cache-Control: no-store`，确保实时性
- 批量获取统计数据：文章列表页一次请求获取多篇文章的统计数据

### 3.2 API 接口

#### 接口1：获取文章统计数据（批量）

- **请求路径**：`/api/stats`
- **请求方式**：GET
- **请求参数**：
  - `ids`：string - 逗号分隔的文章 ID 列表，如 `1,2,3`
- **返回字段**：
  ```json
  {
    "stats": {
      "1": { "viewCount": 128, "readingTime": 5 },
      "2": { "viewCount": 56, "readingTime": 3 }
    }
  }
  ```
- **响应头**：`Cache-Control: no-store`
- **用途**：文章列表页和详情页加载后，客户端请求获取实时统计数据

#### 接口2：记录文章阅读

- **请求路径**：`/api/stats`
- **请求方式**：POST
- **请求参数**：
  - `articleId`：number - 文章 ID
- **返回字段**：
  ```json
  {
    "viewCount": 129
  }
  ```
- **响应头**：`Cache-Control: no-store`
- **用途**：文章详情页加载时调用，递增阅读量并返回最新值

### 3.3 实现要点

1. **CSR 策略分离**
   - 统计数据与文章内容完全分离
   - 文章内容通过 ISR 缓存（revalidate: 3600）
   - 统计数据通过客户端 CSR 实时获取
   - 理由：阅读量频繁变化，不影响 SEO，与 ISR 缓存分离

2. **客户端组件设计**
   - `ArticleStats`：文章详情页使用，挂载时调用 POST 递增阅读量，同时获取 readingTime
   - `ArticleCardStats`：文章卡片使用，仅展示阅读量
   - `ArticleListStats`：文章列表页包装组件，批量获取所有文章的统计数据，通过 props 传递给子组件
   - 所有客户端组件使用 `'use client'` 指令

3. **API 路由实现**
   - GET 请求：解析 `ids` 参数，批量查询 `articles` 表的 `view_count` 和 `reading_time`
   - POST 请求：解析 `articleId`，使用 Sequelize `increment` 方法原子递增 `viewCount`
   - 参数校验：`ids` 最多 50 个，`articleId` 必须为正整数
   - 错误处理：数据库查询失败返回 500

4. **阅读量递增**
   - 使用 Sequelize 的 `Article.increment('viewCount', { where: { id: articleId } })` 原子操作
   - 递增后查询最新值返回给客户端
   - 不做客户端去重（简单计数模式）

5. **加载状态处理**
   - 统计数据加载前显示 `--` 占位符
   - 加载完成后平滑替换为实际数值
   - 加载失败时保持 `--` 显示，不影响页面其他功能

6. **文章详情页集成**
   - `ArticleStats` 组件放在 `ArticleHeader` 下方
   - 接收 `articleId` 作为 props
   - 组件挂载时（`useEffect`）：
     1. 调用 POST `/api/stats` 递增阅读量，获取最新 viewCount
     2. 调用 GET `/api/stats?ids={articleId}` 获取 readingTime
     3. 或合并为一次 POST 请求同时返回 viewCount 和 readingTime

7. **文章列表页集成**
   - 文章列表页是服务端组件，无法直接使用 CSR
   - 创建 `ArticleListStats` 客户端包装组件
   - 该组件接收文章 ID 列表，批量获取统计数据
   - 通过 React Context 或 props 将统计数据传递给各 `ArticleCardStats`

### 3.4 数据流转

```
文章详情页（CSR 统计）:
  页面加载（ISR 静态内容）
    → ArticleStats 客户端组件挂载
    → POST /api/stats { articleId }
    → API: Article.increment('viewCount') + 查询 readingTime
    → 返回 { viewCount, readingTime }
    → 组件更新显示

文章列表页（CSR 统计）:
  页面加载（ISR 静态内容）
    → ArticleListStats 客户端组件挂载
    → GET /api/stats?ids=1,2,3,...
    → API: Article.findAll({ where: { id: ids }, attributes: ['id', 'viewCount', 'readingTime'] })
    → 返回 { stats: { [id]: { viewCount, readingTime } } }
    → 通过 props 传递给各 ArticleCardStats
    → 各卡片更新显示阅读量
```

## 五、注意事项

### 5.1 边界情况

- 文章 ID 不存在：POST 递增时返回 404，GET 批量查询时跳过不存在的 ID
- `ids` 参数为空或格式错误：返回 400 错误
- `ids` 数量超过 50：返回 400 错误，提示超出限制
- `readingTime` 为 0：显示 `< 1 分钟阅读`
- `viewCount` 为 0：正常显示 `0 阅读`

### 5.2 异常处理

- 数据库连接失败：API 返回 500，客户端保持 `--` 占位符
- 网络请求超时：客户端设置 5 秒超时，超时后保持 `--` 显示
- 并发递增：Sequelize `increment` 使用数据库原子操作，天然支持并发安全

### 5.3 性能考虑

- 批量查询：文章列表页一次请求获取所有文章统计数据，避免 N+1 问题
- 无缓存：统计 API 设置 `no-store`，确保数据实时性
- 轻量查询：GET 请求仅查询 `id`、`view_count`、`reading_time` 三个字段

### 5.4 兼容性

- 客户端组件：需要 JavaScript 支持，无 JS 时统计区域显示 `--`
- 暗色模式：统计组件包含 `dark:` 前缀样式
- 响应式：统计信息在移动端和桌面端均正常显示
