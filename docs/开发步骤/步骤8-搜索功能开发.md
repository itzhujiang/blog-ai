## 二、需求说明

### 2.1 功能要求

- 搜索文章标题和摘要，返回匹配的已发布文章列表
- 搜索结果页展示匹配文章（缩略图、标题、摘要、日期、分类）
- 搜索关键词在标题和摘要中高亮显示
- Header 搜索栏支持输入关键词后按 Enter 或点击搜索图标跳转到搜索结果页
- 搜索结果支持分页
- 记录搜索日志（关键词、结果数量、IP、User-Agent）
- 搜索 API 供客户端组件调用

### 2.2 UI 设计要求

根据 UI 设计图（搜索结果页.html）提取的布局要求：

**搜索主区域**：
- 大搜索框：`h-14 rounded-full border-2 border-wood-border`，`bg-off-white`
- 搜索按钮：`h-14 rounded-full bg-wood-light px-8 font-bold text-wood-dark`
- 清除按钮：搜索框内右侧，Material Symbols `close` 图标

**搜索结果统计**：
- 统计信息：`找到 N 个与 "关键词" 相关的结果`
- 关键词高亮：`rounded bg-highlight-bg px-1.5 py-0.5 font-semibold text-wood-dark`
- 排序选项：`相关度排序`、`最新发布`、`最多评论`

**搜索结果卡片**：
- 卡片样式：`rounded-xl border-2 border-wood-border/50 bg-off-white p-6 shadow-natural hover:shadow-natural-hover`

- 底部元信息：日期、分类标签

**分页导航**：
- 复用文章列表页的分页样式（圆形按钮、当前页高亮）

**空状态**：
- 无结果时显示友好提示：`没有找到相关内容，试试其他关键词吧`

### 2.3 业务规则

- 搜索范围：仅搜索文章标题（`title`）和摘要（`excerpt`）
- 仅搜索 `status = 'published'` 且未删除的文章
- 搜索关键词通过 URL 参数传递：`/search?q={keyword}`
- 分页参数：`/search?q={keyword}&page={number}`
- 排序参数：`/search?q={keyword}&sort=relevance|latest|comments`
- 每页显示 10 条结果
- 搜索关键词为空时显示提示，不执行查询
- 搜索关键词最短 1 个字符
- 不向用户展示热门搜索词（PRD 隐私要求）
- 搜索日志仅用于后台分析，不对外暴露

## 三、技术实现指引

### 3.1 技术栈约束

- **前端框架**：Next.js 16.0.1 (App Router) + React 19.2.0
- **样式方案**：Tailwind CSS v4
- **数据库 ORM**：Sequelize 6.x
- **搜索方式**：PostgreSQL `ILIKE` 模糊匹配（通过 Sequelize `Op.iLike`）
- **渲染策略**：搜索结果页使用动态渲染（`force-dynamic`），不缓存

> **搜索方案说明**：技术方案文档提及 PostgreSQL 全文搜索，但全文搜索对中文需要额外扩展（如 `zhparser`）。当前文章数量较少，使用 `ILIKE` 模糊匹配即可满足需求，且天然支持中文。当文章数量超过 1000 篇时，可升级为 GIN 索引全文搜索。

### 3.2 API 接口

#### 接口1：搜索文章

- **请求路径**：`GET /api/search`
- **请求方式**：GET
- **请求参数**：
  - `q`：`string`（必填）- 搜索关键词
  - `page`：`string`（可选，默认 `1`）- 页码
  - `sort`：`string`（可选，默认 `relevance`）- 排序方式（`relevance` | `latest` | `comments`）
- **返回字段**：
  - `articles`：`Array` - 搜索结果列表
    - `id`：`number` - 文章 ID
    - `title`：`string` - 文章标题
    - `slug`：`string` - URL 标识
    - `excerpt`：`string | null` - 文章摘要
    - `publishedAt`：`number | null` - 发布时间戳
    - `thumbnailUrl`：`string | null` - 缩略图 URL
    - `categories`：`Array<{ id, name, slug }>` - 分类列表
  - `total`：`number` - 总结果数
  - `totalPages`：`number` - 总页数
  - `query`：`string` - 搜索关键词（回传）
- **用途**：供搜索结果页和未来客户端组件使用
- **缓存**：不缓存（每次搜索实时查询）

**返回示例**：

```json
{
  "articles": [
    {
      "id": 1,
      "title": "如何学习 TypeScript",
      "slug": "learn-typescript",
      "excerpt": "TypeScript 是 JavaScript 的超集...",
      "publishedAt": 1707350400000,
      "thumbnailUrl": "/images/ts.jpg",
      "categories": [{ "id": 1, "name": "技术学习", "slug": "tech" }]
    }
  ],
  "total": 15,
  "totalPages": 2,
  "query": "TypeScript"
}
```

function highlightKeyword(text: string, keyword: string): React.ReactNode[] {
  if (!keyword || !text) return [text];
  const regex = new RegExp(`(${escapeRegExp(keyword)})`, 'gi');
  const parts = text.split(regex);
  return parts.map((part, i) =>
    regex.test(part)
      ? <mark key={i} className="bg-highlight-bg px-1 dark:bg-primary/20">{part}</mark>
      : part
  );
}

### 3.5 数据获取

#### 搜索结果页数据获取

```typescript
// app/search/page.tsx
export const dynamic = 'force-dynamic'; // 搜索不缓存

const PAGE_SIZE = 10;

async function searchArticles(
  query: string,
  page: number,
  sort: SearchSortType,
): Promise<{ articles: SearchResultItem[]; total: number }> {
  const { initAllModels } = await import('@/utils/models');
  const { Article, ArticleCategory, Category, ArticleMedia, MediaFile } =
    await initAllModels();
  const { Op } = await import('sequelize');

  // 标题或摘要模糊匹配
  const where = {
    status: 'published',
    [Op.or]: [
      { title: { [Op.iLike]: `%${query}%` } },
      { excerpt: { [Op.iLike]: `%${query}%` } },
    ],
  };

  // 排序
  const order = sort === 'latest'
    ? [['publishedAt', 'DESC']]
    : sort === 'comments'
      ? [[Sequelize.literal('"commentCount"'), 'DESC']]
      : [['publishedAt', 'DESC']]; // relevance 暂用时间排序

  const { rows, count } = await Article.findAndCountAll({
    where,
    include: [/* 分类、缩略图关联 */],
    order,
    limit: PAGE_SIZE,
    offset: (page - 1) * PAGE_SIZE,
    distinct: true,
  });

  return { articles: /* 序列化 */, total: count };
}
```

## 五、注意事项

### 5.1 边界情况

- **空关键词**：显示「请输入搜索关键词」提示，不执行查询
- **无匹配结果**：显示「没有找到相关内容，试试其他关键词吧」
- **特殊字符**：搜索关键词中的 `%`、`_` 等 SQL 通配符需要转义
- **超长关键词**：限制关键词最大长度（如 100 字符）
- **单页结果**：总页数为 1 时隐藏分页导航
- **无缩略图**：显示占位区域或隐藏缩略图

### 5.2 异常处理

- **数据库查询失败**：记录错误日志，返回空结果列表
- **搜索日志写入失败**：不影响搜索结果返回（异步写入，catch 忽略）
- **URL 参数非法**：使用默认值（page=1, sort=relevance）

### 5.3 兼容性

- **浏览器支持**：Chrome、Firefox、Safari、Edge 最新版本
- **设备支持**：桌面端优先，移动端基本适配
- **中文搜索**：`ILIKE` 天然支持中文模糊匹配

### 5.4 性能考虑

- 搜索结果页使用 `force-dynamic`，不缓存（搜索结果实时性要求）
- 搜索 API 不设置缓存头
- 搜索日志异步写入，不阻塞搜索结果返回
- `ILIKE` 在文章数量 < 1000 时性能足够
- 搜索仅匹配标题和摘要，不搜索正文内容
- 缩略图使用 `next/image` 懒加载

### 5.5 安全考虑

- 搜索关键词中的 SQL 通配符（`%`、`_`）需要转义，防止意外匹配
- 使用 Sequelize 参数化查询，防止 SQL 注入
- 搜索关键词在页面渲染时由 React 自动转义，防止 XSS
- 高亮函数使用 `escapeRegExp` 转义正则特殊字符
