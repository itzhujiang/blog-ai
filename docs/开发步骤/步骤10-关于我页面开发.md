## 一、步骤目标

实现关于我页面（`/about`），采用 SSG（静态站点生成）策略，在构建时从数据库读取数据生成静态页面。页面包含五个核心区域：个人信息展示、技能专长、成长足迹（时间线）、联系方式、最新动态。所有数据来自 `about_page` 表和关联的 `about_page_media` 表。

## 二、需求说明

### 2.1 功能要求

- 展示博主个人信息：头像、昵称、职业标签、个人标签、自我介绍
- 展示技能专长：按分类分组，每个技能显示名称和熟练度进度条
- 展示成长足迹：时间线形式，按时间倒序排列，显示年龄标记
- 展示联系方式：邮箱、GitHub、微信等联系卡片
- 展示社交媒体链接：Twitter、Dribbble、Instagram 等图标按钮
- 自我介绍内容从关联的 Markdown 文件加载并渲染
- 页面采用 SSG 策略，构建时生成静态 HTML

### 2.3 业务规则

- 数据来源：`about_page` 表（id=1 的记录）
- 头像来源：通过 `about_page_media` 关联表获取 `usageType='avatar'` 的媒体文件
- 自我介绍内容：通过 `about_page_media` 关联表获取 `usageType='content'` 的 Markdown 文件
- 技能数据：`about_page.skills` JSONB 字段，结构为 `[{category, items: [{name, level}]}]`
- 时间线数据：`about_page.timeline` JSONB 字段，结构为 `[{timestamp, title, description}]`
- 联系方式：`about_page.contactInfo` JSONB 字段
- 社交链接：`about_page.socialLinks` JSONB 字段
- 数据不存在时显示友好的空状态提示

### 3.2 数据获取

#### 服务端数据获取（构建时）

关于我页面使用 SSG 策略，在 `page.tsx` 中直接查询数据库：

```typescript
// app/about/page.tsx
export const dynamic = 'force-static';

async function getAboutPageData(): Promise<AboutPageData | null> {
  const { initAllModels } = await import('@/app/utils/models');
  const { AboutPage, AboutPageMedia, MediaFile } = await initAllModels();

  const aboutPage = await AboutPage.findOne({
    where: { id: 1 },
    include: [{
      model: AboutPageMedia,
      as: 'aboutPageMedias',
      include: [{
        model: MediaFile,
        as: 'media',
      }],
    }],
  });

  if (!aboutPage) return null;

  // 提取头像和内容文件
  const avatarMedia = aboutPage.aboutPageMedias?.find(m => m.usageType === 'avatar');
  const contentMedia = aboutPage.aboutPageMedias?.find(m => m.usageType === 'content');

  // 如果有 Markdown 内容文件，通过 HTTP 获取内容
  let introContent = '';
  if (contentMedia?.media?.filePath) {
    const fileUrl = getFileUrl(contentMedia.media.filePath);
    const response = await fetch(fileUrl);
    introContent = await response.text();
  }

  return {
    nickname: aboutPage.nickname,
    jobTitle: aboutPage.jobTitle,
    personalTags: aboutPage.personalTags,
    avatarUrl: avatarMedia?.media?.filePath ? getFileUrl(avatarMedia.media.filePath) : null,
    introContent,
    skills: aboutPage.skills,
    timeline: aboutPage.timeline,
    contactInfo: aboutPage.contactInfo,
    socialLinks: aboutPage.socialLinks,
  };
}
```

### 3.4 实现要点

1. **SSG 策略**
   - 使用 `export const dynamic = 'force-static'` 强制静态生成
   - 构建时从数据库读取数据，生成静态 HTML
   - 数据更新需要重新构建或配合步骤12的 On-Demand Revalidation

2. **组件拆分**
   - `AboutHero`：页面标题和副标题（纯展示，约 30 行）
   - `AboutProfile`：头像 + 昵称 + 标签 + 自我介绍（约 80 行）
   - `AboutSkills`：技能分组 + 进度条（约 80 行）
   - `AboutTimeline`：时间线节点列表（约 100 行）
   - `AboutContact`：联系卡片 + 社交图标（约 120 行）
   - 每个组件控制在 150 行以内，符合项目规范

3. **Markdown 内容渲染**
   - 自我介绍内容存储为 Markdown 文件
   - 通过 `about_page_media` 关联获取文件路径
   - 使用 HTTP 请求获取 Markdown 文本
   - 在 `AboutProfile` 中渲染为 HTML（可使用简单的段落分割，或复用 MDX 渲染逻辑）

4. **头像处理**
   - 通过 `about_page_media` 关联获取 `usageType='avatar'` 的媒体文件
   - 使用 `getFileUrl()` 转换为完整 URL
   - 使用 `next/image` 组件优化图片加载
   - 提供默认占位头像

5. **技能进度条**
   - `level` 值范围 0-100，直接映射为进度条宽度百分比
   - 使用内联 `style={{ width: '${level}%' }}` 设置宽度
   - 背景色 `bg-primary/20`，填充色 `bg-primary/70`

6. **时间线年龄计算**
   - `timestamp` 为毫秒级 Unix 时间戳
   - 根据时间戳计算当时的年龄（或直接使用数据中的标记）
   - 按时间倒序排列（最新的在上方）
   - 圆形标记大小随重要程度/时间远近变化

7. **联系方式图标**
   - 使用 Material Symbols 图标（`mail`、`code`、`chat`）
   - 社交媒体使用内联 SVG 图标
   - 悬停时显示品牌色（Twitter 蓝、Dribbble 粉等）

8. **响应式设计**
   - 个人信息：移动端单列，桌面端 1:2 网格
   - 技能区域：移动端单列，平板双列，桌面三列
   - 联系卡片：移动端单列，平板双列，桌面三列
   - 时间线：所有尺寸保持左侧布局，移动端减小间距

9. **暗色模式**
   - 所有组件包含 `dark:` 前缀样式
   - 背景色：`bg-background-light dark:bg-background-dark`
   - 文字色：`text-text-light dark:text-text-dark`
   - 边框色：`border-primary/20 dark:border-primary/30`

### 3.5 数据流转

```
构建时（SSG）:
  数据库 about_page 表 → getAboutPageData()
    ├── AboutPage.findOne({ include: AboutPageMedia → MediaFile })
    ├── 提取 avatar 媒体 → getFileUrl() → avatarUrl
    ├── 提取 content 媒体 → fetch Markdown → introContent
    └── 返回 AboutPageData

页面渲染:
  page.tsx → getAboutPageData() → 传递 props 给子组件
    ├── <AboutHero />
    ├── <AboutProfile nickname, jobTitle, personalTags, avatarUrl, introContent />
    ├── <AboutSkills skills />
    ├── <AboutTimeline timeline />
    └── <AboutContact contactInfo, socialLinks />
```

## 五、注意事项

### 5.1 边界情况

- 数据库无 about_page 记录：显示默认空状态页面，提示 "页面内容正在准备中"
- 无头像媒体关联：显示默认占位头像（可使用首字母头像或默认图片）
- 无 Markdown 内容文件：自我介绍区域显示空状态或默认文本
- 技能数据为空：隐藏技能专长区域
- 时间线数据为空：隐藏成长足迹区域
- 联系方式为空：隐藏联系方式区域
- 社交链接为空：隐藏社交媒体图标区域
- Markdown 文件获取失败：降级显示空内容，不影响页面其他区域

### 5.2 异常处理

- 数据库查询失败：捕获异常，返回 null，页面显示空状态
- 媒体文件 URL 无效：`next/image` 使用 fallback 图片
- Markdown 文件 fetch 失败：try/catch 捕获，introContent 设为空字符串

### 5.3 性能考虑

- SSG 策略：构建时生成静态 HTML，无运行时数据库查询
- `next/image`：自动优化头像图片大小和格式
- 进度条动画：使用 CSS transition，不依赖 JavaScript

### 5.4 兼容性

- 移动端：所有区域自适应单列布局
- 暗色模式：所有组件包含 `dark:` 前缀样式
- 无 JavaScript：SSG 页面完全可用，无需客户端 JS
