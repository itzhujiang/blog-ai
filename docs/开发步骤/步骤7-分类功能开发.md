# 步骤7：分类功能开发

## 步骤信息

- **步骤序号**：7 / 12
- **关联 PRD 功能**：分类筛选、分类页面
- **前置步骤**：步骤5（文章列表页）、步骤6（文章详情页）
- **预计工作量**：中等

---

## 一、步骤目标

在步骤5已实现基础分类筛选（CategoryFilter 组件 + URL 参数）的基础上，完善分类功能：创建分类 API 路由供客户端使用、增强分类筛选体验（显示各分类文章数量）、为分类筛选页添加动态 SEO 元数据、创建分类标签云组件供首页和侧边栏复用。

---

## 二、需求说明

### 2.1 功能要求

- 创建分类列表 API（`GET /api/categories`），返回所有分类及其文章数量
- 文章列表页按分类筛选时，页面标题和描述应动态反映当前分类
- CategoryFilter 组件增强：每个分类标签旁显示文章数量
- 首页添加分类导航区域，展示所有分类及文章数量，点击跳转到对应分类的文章列表

### 2.2 UI 设计要求

- 分类标签显示格式：`分类名 (N)`，N 为该分类下已发布文章数量
- 首页分类导航区域：水平排列的分类卡片，每个卡片包含分类名和文章数量
- 分类卡片样式与暖木主题一致：圆角、primary 色调边框、hover 效果

### 2.3 业务规则

- 只统计 `status = 'published'` 的文章数量
- 分类按名称字母顺序排列
- 文章数量为 0 的分类仍然显示（不隐藏）
- 分类筛选时 URL 格式：`/articles?category={slug}`
- SEO 标题格式：`{分类名} - 文章 - 暖木博客`

## 三、技术实现指引

### 3.1 涉及文件

| 文件路径 | 操作类型 | 说明 |
|---------|---------|-----|
| `app/api/categories/route.ts` | 新增 | 分类列表 API，返回分类及文章数量 |
| `app/articles/types/article-list.types.ts` | 修改 | CategoryTag 接口添加 articleCount 字段 |
| `app/articles/components/CategoryFilter.tsx` | 修改 | 显示各分类文章数量 |
| `app/articles/page.tsx` | 修改 | 添加 generateMetadata 动态 SEO、getCategories 返回文章数量 |
| `app/components/CategoryNav.tsx` | 新增 | 首页分类导航组件（服务端组件） |
| `app/page.tsx` | 修改 | 引入 CategoryNav 组件 |

### 3.2 API 接口

#### 接口1：获取分类列表

- **请求路径**：`GET /api/categories`
- **请求方式**：GET
- **请求参数**：无
- **返回字段**：
  - `categories`：`Array` - 分类列表
    - `id`：`number` - 分类 ID
    - `name`：`string` - 分类名称
    - `slug`：`string` - URL 标识
    - `articleCount`：`number` - 已发布文章数量
- **用途**：供客户端组件获取分类数据（如搜索页侧边栏等场景）

**返回示例**：

```json
{
  "categories": [
    { "id": 1, "name": "AI创作", "slug": "ai", "articleCount": 5 },
    { "id": 2, "name": "技术学习", "slug": "tech", "articleCount": 12 },
    { "id": 3, "name": "生活故事", "slug": "life", "articleCount": 8 }
  ]
}
```

### 3.3 实现要点

1. **分类文章数量查询**
   - 使用 Sequelize 的 `Sequelize.literal` 子查询统计每个分类的已发布文章数
   - SQL 子查询：`SELECT COUNT(*) FROM article_categories ac JOIN articles a ON ac.article_id = a.id WHERE ac.category_id = "Category".id AND a.status = 'published' AND a.deleted_at IS NULL`
   - 与文章列表页的 commentCount 子查询模式一致

2. **动态 SEO 元数据**
   - 在 `app/articles/page.tsx` 中添加 `generateMetadata` 函数
   - 根据 `searchParams.category` 参数动态生成标题和描述
   - 无分类筛选时：`所有文章 - 暖木博客`
   - 有分类筛选时：`{分类名} - 文章 - 暖木博客`

3. **CategoryFilter 增强**
   - CategoryTag 接口新增 `articleCount?: number` 可选字段（保持向后兼容）
   - 有 articleCount 时显示 `分类名 (N)` 格式
   - 无 articleCount 时仅显示分类名（兼容旧调用方式）

4. **首页分类导航**
   - 服务端组件，直接查询数据库
   - 复用 `getCategories` 数据获取逻辑（含文章数量）
   - 放置在 HeroSection 和 LatestArticles 之间

5. **API 路由实现**
   - 使用动态 import `initAllModels` 避免循环依赖
   - 返回 `NextResponse.json()`
   - try/catch 包裹，失败返回 500 状态码
   - 设置 Cache-Control 响应头：`public, s-maxage=3600, stale-while-revalidate=86400`

### 3.4 数据流转

```
服务端页面渲染（ISR）:
  数据库 → getCategories() → CategoryFilter 组件（含文章数量）
  数据库 → getCategories() → CategoryNav 首页组件

客户端 API 调用（未来搜索页等场景）:
  客户端 → GET /api/categories → NextResponse.json → 客户端组件
```

## 五、注意事项

### 5.1 边界情况

- 分类下无文章时：显示 `分类名 (0)`，不隐藏该分类
- 数据库中无分类数据时：CategoryFilter 只显示"全部"按钮，首页分类导航区域隐藏
- URL 中 category 参数对应的分类不存在时：显示空文章列表，不报错

### 5.2 异常处理

- API 路由数据库查询失败：返回 500 状态码和错误信息 `{ error: '获取分类失败' }`
- 服务端 getCategories 失败：返回空数组，页面正常渲染（降级处理）

### 5.3 兼容性

- CategoryTag 接口的 `articleCount` 字段设为可选（`articleCount?: number`），确保不影响已有组件
- 文章详情页 ArticleFooter 中的分类标签不需要显示数量，保持现有样式
