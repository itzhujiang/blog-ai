# 步骤9：评论系统开发

## 步骤信息

- **步骤序号**：9 / 12
- **关联 PRD 功能**：3.1.3 互动功能 - 评论系统
- **前置步骤**：步骤6（文章详情页开发）
- **预计工作量**：复杂

---

## 一、步骤目标

在文章详情页底部实现完整的评论系统，包括：评论列表展示（支持嵌套回复）、访客评论表单、评论 API（获取列表 + 发表评论）、相对时间显示、作者徽章。评论区采用 CSR（客户端渲染）策略，不影响文章页面的 ISR 缓存。

---

## 二、需求说明

### 2.1 功能要求

- 支持嵌套回复（无限层级，但前端展示限制为 2 层：顶级评论 + 回复）
- 访客评论模式（无需注册，仅需填写昵称）
- 评论默认为 `pending` 状态，需审核后才显示（前端仅展示 `approved` 状态的评论）
- 作者回复显示「作者」徽章
- 评论数实时显示在评论区标题中
- 发表评论后显示「评论已提交，等待审核」提示

### 2.2 UI 设计要求

参考 `docs/UI/文章详情页.html` 第 269-356 行的评论区设计：

- **评论表单**：
  - 圆角卡片背景 `bg-primary/5 dark:bg-primary/10`
  - 昵称输入框（单行，`rounded-lg`）
  - 评论内容文本域（4 行，`rounded-lg`）
  - 「发表评论」按钮（CTA 绿色，`rounded-full`）

- **评论列表**：
  - 用户头像（圆形 40x40，使用首字母生成默认头像）
  - 作者名（加粗）+ 时间（相对时间：3小时前、昨天等）
  - 评论内容（`text-sm`）
  - 嵌套回复缩进 `ml-8`
  - 作者徽章：`bg-cta-light/20 text-cta-light` 圆角标签

- **回复交互**：
  - 每条评论下方显示「回复」按钮
  - 点击后在该评论下方展开回复表单
  - 回复表单包含昵称 + 内容 + 提交/取消按钮

### 2.3 业务规则

- 评论内容不能为空，昵称不能为空
- 昵称最长 100 字符，评论内容最长 2000 字符
- 仅展示 `status = 'approved'` 的评论
- 评论按 `createdAt ASC` 排序（旧的在前）
- 嵌套回复按 `createdAt ASC` 排序
- 记录评论者 IP 地址（从请求头获取）
- 作者判断：`authorName` 匹配站点配置中的 `authorName` 时显示作者徽章

### 3.2 API 接口

#### 接口1：获取评论列表

- **请求路径**：`GET /api/comments`
- **请求方式**：GET
- **请求参数**：
  - `articleId`：number（必填）- 文章 ID
- **返回字段**：
  ```json
  {
    "comments": [
      {
        "id": 1,
        "authorName": "旅人A",
        "content": "这篇文章说出了我的心声！",
        "createdAt": 1707350400000,
        "isAuthor": false,
        "replies": [
          {
            "id": 2,
            "authorName": "木心",
            "content": "很高兴你喜欢！",
            "createdAt": 1707357600000,
            "isAuthor": true,
            "parentId": 1
          }
        ]
      }
    ],
    "total": 5
  }
  ```
- **用途**：客户端加载评论列表，构建嵌套结构

#### 接口2：发表评论

- **请求路径**：`POST /api/comments`
- **请求方式**：POST
- **请求参数**（JSON body）：
  - `articleId`：number（必填）- 文章 ID
  - `parentId`：number | null（可选）- 父评论 ID（回复时传入）
  - `authorName`：string（必填）- 昵称，最长 100 字符
  - `content`：string（必填）- 评论内容，最长 2000 字符
- **返回字段**：
  ```json
  {
    "message": "评论已提交，等待审核",
    "comment": {
      "id": 3,
      "authorName": "新用户",
      "content": "很棒的文章！",
      "createdAt": 1707364800000,
      "status": "pending"
    }
  }
  ```
- **用途**：提交新评论或回复

### 3.3 实现要点

1. **CSR 策略**
   - CommentSection 是 `'use client'` 组件
   - 使用 `useEffect` + `fetch` 在客户端加载评论
   - 不影响文章页面的 ISR 缓存
   - 加载中显示骨架屏或 loading 状态

2. **嵌套评论数据结构**
   - API 返回扁平列表，前端构建树形结构
   - 顶级评论：`parentId === null`
   - 回复：`parentId !== null`，挂载到对应父评论的 `replies` 数组
   - 前端展示限制 2 层（顶级 + 回复），深层回复平铺到第 2 层

3. **相对时间显示**
   - 实现 `formatRelativeTime()` 工具函数
   - 规则：< 1分钟 → "刚刚"，< 1小时 → "N分钟前"，< 24小时 → "N小时前"，< 7天 → "N天前"，< 30天 → "N周前"，其他 → "YYYY年M月D日"

4. **评论头像**
   - 使用昵称首字母生成彩色圆形头像
   - 背景色根据昵称 hash 从预设色板中选取
   - 无需外部头像服务

5. **作者徽章判断**
   - API 端：从 `site_settings` 表读取 `authorName` 配置
   - 比较评论的 `authorName` 与站点 `authorName`
   - 匹配时在返回数据中标记 `isAuthor: true`

6. **XSS 防护**
   - React 自动转义评论内容（JSX 中直接渲染文本）
   - API 端对输入进行 trim 和长度校验
   - 不允许 HTML 标签（纯文本评论）

7. **回复交互状态**
   - CommentSection 维护 `replyingTo: number | null` 状态
   - 点击「回复」设置 `replyingTo` 为该评论 ID
   - 回复表单出现在对应评论下方
   - 提交或取消后重置 `replyingTo` 为 null

### 3.4 数据流转

```
文章详情页（ISR 服务端渲染）:
  数据库 → getArticle() → ArticleHeader/Content/Footer
  传递 articleId 给 CommentSection（客户端组件）

评论区（CSR 客户端渲染）:
  useEffect → fetch GET /api/comments?articleId=N → 构建嵌套结构 → 渲染 CommentItem 列表

发表评论:
  CommentForm → fetch POST /api/comments → 成功提示 → 刷新评论列表

回复评论:
  点击「回复」→ 展开 CommentForm(parentId) → fetch POST → 成功提示 → 刷新列表
```

## 五、注意事项

### 5.1 边界情况

- 文章无评论时：显示空状态提示 "暂无评论，来说两句吧"
- 评论内容过长：前端限制 2000 字符，API 端二次校验
- 昵称为空或仅空格：前端 trim 后校验，API 端二次校验
- 深层嵌套回复：前端展示限制 2 层，第 3 层及以上平铺到第 2 层并显示 `@被回复人`
- 并发提交：提交按钮在请求期间禁用，防止重复提交

### 5.2 异常处理

- API 请求失败：显示错误提示，允许重试
- 评论加载失败：显示 "评论加载失败，点击重试" 提示
- 网络超时：设置合理的请求超时时间

### 5.3 兼容性

- 移动端：评论表单全宽，回复缩进减小
- 暗色模式：所有组件包含 `dark:` 前缀样式
- 无 JavaScript：评论区不可用（CSR 依赖），文章内容不受影响
