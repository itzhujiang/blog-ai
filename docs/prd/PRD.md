# 个人博客项目 PRD (产品需求文档)

## 1. 项目概述

### 1.1 项目背景
项目旨在创建一个个人成长分享博客，集生活故事分享、技术学习记录、AI作品展示于一体。

### 1.2 项目目标
- 搭建个人品牌展示平台
- 记录和分享技术学习心得
- 分享个人生活故事和成长感悟
- 展示AI创作作品
- 与读者建立连接和交流

### 1.3 项目范围
- 博客展示系统（前端项目）
- 内容管理系统（独立项目）
- 共用PostgreSQL数据库

### 1.4 技术栈
- **前端框架**: Next.js 16.x
- **数据库**: PostgreSQL
- **部署环境**: 阿里云ECS
- **开发环境**: 本地PostgreSQL + Next.js

## 2. 用户研究

### 2.1 目标用户画像

**主要用户群体:**
- 技术同行开发者（对技术学习内容感兴趣）
- 有相同学习兴趣的初学者
- 对个人成长故事感兴趣的读者
- 对AI艺术创作感兴趣的访客

**用户特征:**
- 具备一定技术背景
- 关注个人成长和学习
- 喜欢深度阅读和思考
- 愿意通过评论进行交流

### 2.2 用户场景分析

**使用场景:**
1. **学习场景**: 搜索特定技术主题的学习资料
2. **浏览场景**: 随意浏览最新发布的内容
3. **互动场景**: 对感兴趣的内容进行评论交流
4. **分享场景**: 将有价值的内容分享到社交媒体

## 3. 功能规格

### 3.1 核心功能模块

#### 3.1.1 内容展示模块

**文章系统:**
- 文章列表页面（支持分页，图文并茂展示）
- 文章详情页面（富文本展示）
- 文章分类浏览
- 搜索功能（搜索文章标题和摘要）

**个人页面:**
- 关于我页面（自我介绍、联系方式）
- 个人照片展示

#### 3.1.2 分类系统

**三大主要分类:**
- 技术学习：编程经验、技术心得、学习笔记
- 生活故事：工作感悟、生活记录、思考分享
- AI创作：AI图片作品、创作心得

**分类特性:**
- 一篇文章可以属于多个分类
- 所有分类平等，不区分主次
- 用户可以通过分类浏览相关主题的文章
- 分类导航清晰，便于内容组织

#### 3.1.3 互动功能

**评论系统:**
- 支持嵌套回复
- 访客评论模式（无需注册）
- 评论审核机制（默认待审核状态）
- 评论点赞功能
- 博主回复显示"作者"标识
- 基本的评论管理（删除、审核、标记垃圾评论）

**分享功能:**
- 社交媒体分享（微信、微博、Twitter）
- 复制链接功能

**搜索功能:**
- 搜索范围：文章标题和摘要
- 搜索结果页面展示匹配的文章列表
- 记录搜索历史用于后续分析
- 不向用户展示热门搜索词

### 3.2 页面结构设计

```
/                     - 首页（最新文章列表）
/articles             - 文章列表页（支持分页）
/articles/[slug]      - 文章详情页
/about                - 关于我页面
/search               - 搜索结果页
```

### 3.3 管理功能（独立项目）

**内容管理:**
- 文章发布/编辑/删除
- 分类管理
- 评论审核和管理

### 4.2 数据库设计

#### 4.2.1 核心表结构

**文章表 (articles)**

存储文章的基本信息和元数据。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 文章唯一标识 |
| title | 字符串 | 文章标题 |
| slug | 字符串 | URL友好的标识符（唯一） |
| excerpt | 文本 | 文章摘要 |
| author_name | 字符串 | 作者名称 |
| reading_time | 整数 | 预计阅读时长（分钟） |
| status | 枚举 | 文章状态（draft/published/archived） |
| view_count | 整数 | 浏览次数 |
| published_at | 时间戳 | 发布时间 |
| created_at | 时间戳 | 创建时间 |
| updated_at | 时间戳 | 更新时间 |

**说明**：
- 文章内容以 Markdown 文件形式存储在服务端文件系统
- 通过 `article_media` 关联表连接到 `media_files` 表获取内容文件路径
- 文章缩略图也通过 `article_media` 关联表管理

---

**分类表 (categories)**

存储文章分类信息。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 分类唯一标识 |
| name | 字符串 | 分类名称 |
| slug | 字符串 | URL友好的标识符（唯一） |
| created_at | 时间戳 | 创建时间 |
| updated_at | 时间戳 | 更新时间 |

**初始分类数据**：
- 技术学习：编程技术、开发经验、学习笔记
- 生活故事：生活记录、工作感悟、思考分享
- AI创作：AI艺术作品、创作心得

---

**文章分类关联表 (article_categories)**

实现文章与分类的多对多关系。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| article_id | 外键 | 关联文章ID |
| category_id | 外键 | 关联分类ID |
| created_at | 时间戳 | 关联创建时间 |

**说明**：
- 一篇文章可以属于多个分类
- 所有分类平等，不区分主次
- 删除文章时自动删除关联记录

---

**评论表 (comments)**

存储文章评论信息，支持嵌套回复。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 评论唯一标识 |
| article_id | 外键 | 关联文章ID |
| parent_id | 外键 | 父评论ID（支持嵌套回复） |
| author_name | 字符串 | 评论者名称 |
| author_email | 字符串 | 评论者邮箱（选填） |
| author_url | 字符串 | 评论者网站（选填） |
| author_ip | 字符串 | 评论者IP地址 |
| content | 文本 | 评论内容 |
| status | 枚举 | 评论状态（pending/approved/spam/trash） |
| like_count | 整数 | 点赞数 |
| created_at | 时间戳 | 评论时间 |
| updated_at | 时间戳 | 更新时间 |

**说明**：
- 支持无限层级嵌套回复
- 访客评论模式（无需注册）
- 评论默认为待审核状态（pending）
- 支持评论点赞功能
- 博主回复评论时显示"作者"标识

---

**媒体文件表 (media_files)**

统一管理所有媒体文件（图片、文章内容文件等）。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 媒体文件唯一标识 |
| original_name | 字符串 | 原始文件名 |
| stored_name | 字符串 | 存储文件名 |
| file_path | 字符串 | 服务端存储路径 |
| file_url | 字符串 | 访问URL |
| file_size | 整数 | 文件大小（字节） |
| mime_type | 字符串 | 文件MIME类型 |
| width | 整数 | 图片宽度 |
| height | 整数 | 图片高度 |
| alt_text | 文本 | 图片描述（用于无障碍访问） |
| uploader_name | 字符串 | 上传者名称 |
| file_hash | 字符串 | 文件MD5哈希值（用于去重） |
| created_at | 时间戳 | 上传时间 |
| updated_at | 时间戳 | 更新时间 |

---

**文章媒体关联表 (article_media)**

管理文章与媒体文件的关联关系。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 关联记录唯一标识 |
| article_id | 外键 | 关联文章ID |
| media_id | 外键 | 关联媒体文件ID |
| usage_type | 枚举 | 使用类型（thumbnail/attachment/content） |
| sort_order | 整数 | 排序权重 |
| created_at | 时间戳 | 关联创建时间 |

**使用类型说明**：
- `thumbnail`：文章列表缩略图
- `attachment`：文章正文中的附件图片
- `content`：文章内容文件（Markdown格式）

---

**关于页面表 (about_page)**

存储"关于我"页面的信息。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 页面唯一标识 |
| title | 字符串 | 页面标题 |
| nickname | 字符串 | 博主昵称 |
| job_title | 字符串 | 职业标签 |
| personal_tags | JSON | 个人标签数组 |
| contact_info | JSON | 联系方式（邮箱、GitHub、微信等） |
| social_links | JSON | 社交媒体链接 |
| skills | JSON | 技能专长（分类和等级） |
| timeline | JSON | 成长足迹时间线 |
| updated_at | 时间戳 | 更新时间 |

**说明**：
- 个人简介内容通过 `about_page_media` 关联表管理，使用 Markdown 文件存储
- 头像图片也通过 `about_page_media` 关联表管理

---

**搜索日志表 (search_logs)**

记录用户搜索行为，用于分析和优化。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | 主键 | 日志唯一标识 |
| query | 字符串 | 搜索关键词 |
| results_count | 整数 | 搜索结果数量 |
| ip_address | 字符串 | 用户IP地址 |
| user_agent | 文本 | 用户代理信息 |
| created_at | 时间戳 | 搜索时间 |

**说明**：
- 记录所有搜索行为用于后续分析
- 不向用户展示热门搜索词

### 4.3 前端技术实现

#### 4.3.1 技术选型
- **框架**: Next.js 16.x (App Router)
- **样式**: Tailwind CSS
- **数据库ORM**: sequelize
- **富文本编辑**: MDX 或 Tiptap
- **图片处理**: next/image 组件

#### 4.3.2 关键功能实现

**数据获取策略:**
- 文章列表: ISR (Incremental Static Regeneration)
- 文章详情: SSR (Server-Side Rendering)
- 评论: CSR (Client-Side Rendering)

**性能优化:**
- 图片懒加载
- 代码分割
- 字体优化
- 缓存策略

## 8. 风险评估

### 8.1 技术风险

**数据库风险:**
- 数据库连接配置错误
- SQL注入安全风险
- 数据备份策略缺失

**应对策略:**
- 使用sequelize ORM防止SQL注入
- 配置数据库连接池
- 设置定时备份脚本

**性能风险:**
- 图片过多影响加载速度
- 数据库查询性能问题
- 内存使用过高

**应对策略:**
- 图片压缩和懒加载
- 数据库索引优化
- 使用Next.js的性能优化功能

**安全风险:**
- XSS攻击
- CSRF攻击
- 敏感信息泄露

**应对策略:**
- 输入验证和输出编码
- 使用CSP头
- 环境变量管理敏感配置

### 8.2 项目风险

**开发风险:**
- 功能复杂度超出预期
- 技术难点攻关时间不足
- 调试和测试时间不够

**应对策略:**
- 按阶段开发，优先核心功能
- 预留缓冲时间
- 及时记录问题和解决方案

### 8.3 运维风险

**部署风险:**
- ECS环境配置复杂
- 域名和SSL证书配置
- 防火墙和安全组设置

**应对策略:**
- 提前熟悉Linux基本操作
- 准备详细的部署文档
- 使用成熟的部署脚本
