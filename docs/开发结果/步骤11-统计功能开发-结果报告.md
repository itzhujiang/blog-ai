## 三、架构说明

### 3.1 API 设计

**GET /api/stats?ids=1,2,3**
- 解析 ids 参数，校验（最多 50 个正整数）
- 查询 `Article.findAll({ where: { id: ids }, attributes: ['id', 'viewCount', 'readingTime'] })`
- 返回 `{ stats: { "1": { viewCount: 128, readingTime: 5 }, ... } }`
- 响应头 `Cache-Control: no-store`

**POST /api/stats**
- Body：`{ articleId: number }`
- `Article.increment('viewCount', { where: { id: articleId } })`
- 查询递增后的值并返回 `{ viewCount: 129, readingTime: 5 }`
- 文章不存在返回 404
- 响应头 `Cache-Control: no-store`

### 3.2 数据流转

```
详情页（ArticleStats）:
  useEffect → POST /api/stats { articleId }
  → 递增 viewCount → 返回 { viewCount, readingTime }
  → 渲染 visibility 图标 + 阅读数 + schedule 图标 + 阅读时间

列表页（ArticleListClient）:
  useEffect → GET /api/stats?ids=1,2,3
  → 返回 { stats: { ... } } → 构建 statsMap
  → ArticleCard viewCount={statsMap[id]?.viewCount}

搜索页（SearchResultsClient）:
  useEffect → GET /api/stats?ids=1,2,3
  → 返回 { stats: { ... } } → 构建 statsMap
  → SearchResultCard viewCount={statsMap[id]?.viewCount}
```

### 3.3 关键技术实现

- **CSR 与 ISR 分离**：统计数据通过客户端组件（`'use client'`）实时获取，不影响文章页 ISR 缓存
- **批量查询避免 N+1**：列表页和搜索页各只发 1 次 GET 请求，批量获取所有文章的统计数据
- **详情页 POST 递增**：每次访问详情页自动递增阅读量，同时返回最新统计数据
- **优雅降级**：统计数据加载前显示 `--` 占位符，加载失败静默处理不影响页面
- **readingTime 边界处理**：readingTime=0 时显示 `< 1 分钟阅读`
- **ids 参数校验**：最多 50 个正整数，防止滥用
