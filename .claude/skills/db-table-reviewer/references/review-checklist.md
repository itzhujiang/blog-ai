# 数据库表设计审查检查清单

## 1. 业务场景验证

- [ ] 每张表是否对应一个明确的业务实体？
- [ ] 表的 CRUD 场景是否清晰（谁创建、谁读取、谁更新、谁删除）？
- [ ] 是否存在"僵尸表"（设计了但实际不会被使用）？
- [ ] 表的数据生命周期是什么（创建后多久会被查询/归档/删除）？

## 2. 字段设计

### 必要性
- [ ] 每个字段是否都有明确的业务用途？
- [ ] 是否存在可以通过计算得出而无需存储的字段？
- [ ] 是否有字段在当前需求中未被使用（过度设计）？

### 数据类型
- [ ] VARCHAR 长度是否基于实际数据范围而非默认 255？
- [ ] 数值类型是否匹配实际范围（INTEGER vs BIGINT vs SMALLINT）？
- [ ] 时间字段类型选择是否合理（TIMESTAMP vs BIGINT vs DATE）？
- [ ] 布尔值是否用 BOOLEAN 而非 INTEGER/CHAR？
- [ ] JSON/JSONB 字段是否真的需要灵活 schema，还是应该拆为独立字段？
- [ ] TEXT vs VARCHAR 的选择是否合理？

### 默认值与约束
- [ ] NOT NULL 约束是否合理（哪些字段允许为空）？
- [ ] DEFAULT 值是否符合业务逻辑？
- [ ] UNIQUE 约束是否覆盖了业务唯一性要求？
- [ ] CHECK 约束是否用于限制枚举值或数值范围？

## 3. 主键设计

- [ ] 主键类型选择是否合理（SERIAL vs BIGSERIAL vs UUID）？
- [ ] 是否需要复合主键？复合主键的字段顺序是否正确？
- [ ] 自增主键是否会暴露业务信息（如用户数量）？
- [ ] UUID 的性能影响是否可接受（索引大小、插入性能）？

## 4. 关系设计

### 外键
- [ ] 外键的 ON DELETE 策略是否正确（CASCADE / RESTRICT / SET NULL）？
- [ ] 外键的 ON UPDATE 策略是否需要设置？
- [ ] 是否存在循环外键依赖？
- [ ] 外键引用的字段类型是否与被引用字段一致？

### 关系类型
- [ ] 一对多 vs 多对多的选择是否反映真实业务关系？
- [ ] 多对多关联表是否需要额外字段（如排序、创建时间）？
- [ ] 自引用关系（如评论嵌套）的层级限制是否考虑？
- [ ] 是否存在可以合并的冗余关联表？

## 5. 索引策略

- [ ] 主要查询条件是否都有对应索引？
- [ ] 复合索引的字段顺序是否匹配查询模式（最左前缀原则）？
- [ ] 是否存在冗余索引（被其他索引覆盖）？
- [ ] 高频写入的表是否索引过多（影响写入性能）？
- [ ] 唯一索引是否覆盖了业务唯一性约束？
- [ ] 是否需要部分索引（WHERE 条件索引）？
- [ ] 排序字段是否有索引支持？

## 6. 命名规范

- [ ] 表名是否统一使用复数/单数？
- [ ] 字段名是否统一使用 snake_case？
- [ ] 外键字段命名是否一致（如 `xxx_id`）？
- [ ] 枚举类型命名是否清晰且不与表名冲突？
- [ ] 索引命名是否有统一规则（如 `idx_表名_字段名`）？
- [ ] 布尔字段是否使用 `is_` / `has_` 前缀？

## 7. 时间戳与审计

- [ ] created_at / updated_at 是否全局统一？
- [ ] 时间戳类型是否全局一致（不混用 TIMESTAMP 和 BIGINT）？
- [ ] updated_at 的自动更新机制是否配置（触发器或应用层）？
- [ ] 是否需要操作审计（谁在什么时候做了什么修改）？

## 8. 软删除

- [ ] 哪些表需要软删除，哪些可以硬删除？
- [ ] 软删除字段是否统一（deleted_at vs is_deleted）？
- [ ] 查询时是否都加了软删除过滤条件？
- [ ] 软删除数据的清理策略是什么？
- [ ] 唯一索引是否考虑了软删除（避免已删除数据阻止新数据）？

## 9. 安全性

- [ ] 密码是否使用安全的哈希算法（bcrypt/argon2 而非 MD5/SHA1）？
- [ ] 敏感数据（手机号、邮箱、IP）是否需要加密存储或脱敏？
- [ ] 是否有防止 SQL 注入的参数化查询？
- [ ] 用户输入字段的长度限制是否合理（防止存储攻击）？
- [ ] 是否需要数据访问审计日志？

## 10. 性能与扩展

- [ ] 预估数据量下的查询性能是否可接受？
- [ ] 是否需要分区策略（按时间、按 ID 范围）？
- [ ] 热点数据是否需要缓存层？
- [ ] 大文本字段是否应该拆到独立表？
- [ ] 是否存在 N+1 查询风险的关系设计？
- [ ] 统计类字段（count）是冗余存储还是实时计算？

## 11. 文档一致性

- [ ] ER 图与实际建表语句是否一致？
- [ ] 初始化数据与表结构是否匹配（字段名、类型）？
- [ ] 示例查询中引用的字段是否都存在于表中？
- [ ] 枚举值在文档描述和 SQL 定义中是否一致？
