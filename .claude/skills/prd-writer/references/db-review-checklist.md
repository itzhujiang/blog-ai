## 2. 表结构审查

### 2.1 通用字段检查

每张表都应该回答以下问题：

| 字段 | 问题 |
|------|------|
| id | 主键类型？自增还是 UUID？ |
| created_at | 创建时间是否需要？ |
| updated_at | 更新时间是否需要？ |
| deleted_at | 是否需要软删除？ |
| created_by | 是否需要记录创建人？ |

### 2.2 字段类型检查

| 检查项 | 问题 |
|--------|------|
| 精度选择 | INT 的大小是否合适？VARCHAR 长度是否足够？ |
| 时间类型 | DATETIME vs TIMESTAMP vs DATE？ |
| 文本类型 | TEXT vs VARCHAR vs JSON？ |
| 数值类型 | DECIMAL vs FLOAT vs INT？ |
| 枚举类型 | 枚举值是否可能扩展？ |

### 2.3 字段约束检查

| 约束 | 问题 |
|------|------|
| 必填 | 为什么这个字段是必填/可选？ |
| 默认值 | 默认值是否合理？ |
| 唯一 | 这个组合是否可能重复？ |
| 索引 | 查询时按这个字段过滤吗？ |

---

## 3. 索引审查

### 3.1 索引类型确认

| 索引类型 | 使用场景 | 确认问题 |
|----------|----------|----------|
| 主键 | 唯一标识 | 是否有业务含义？ |
| 唯一索引 | 唯一约束 | 这个组合是否真的需要唯一？ |
| 普通索引 | 查询过滤 | 查询时真的会按这个字段过滤吗？ |
| 联合索引 | 多条件查询 | 字段顺序是否最优？ |
| 全文索引 | 文本搜索 | 搜索频率和性能要求如何？ |

### 3.2 索引审查问题

- "这个索引是为什么查询设计的？"
- "这个联合索引的字段顺序是否考虑了查询频率？"
- "为什么不用联合索引而用多个单字段索引？"
- "索引是否会降低写入性能？"

## 10. 与用户对话模板

### 数据库设计审对话示例

```
我已经查看了你的数据库设计，有几个问题需要确认：

关于 [表A]：
1. 这个字段设置为必填，用户在什么场景下填写？
2. 这个索引是为了优化什么查询？
3. 删除记录时，关联数据如何处理？

关于 [关联关系]：
1. 表A和表B是一对多关系，外键放在B表对吗？
2. 删除A表记录时，B表的记录需要级联删除吗？

关于 [性能]：
1. 预计单表最大数据量是多少？
2. 哪些查询最频繁？是否需要额外索引？

请回答这些问题，帮助我理解设计意图。
```

### 追问技巧

| 场景 | 提问方式 |
|------|----------|
| 不理解设计 | "这个设计是出于什么考虑？" |
| 质疑设计 | "如果改成...会有什么影响？" |
| 确认理解 | "我的理解是...对吗？" |
| 探索替代 | "有没有考虑过另一种方案？" |

## 11. 常见问题清单

### 11.1 设计问题

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| 主键使用业务字段 | 高 | 应使用无意义的代理键 |
| 字段命名不一致 | 中 | 同概念应同名 |
| 缺乏软删除 | 中 | 重要数据应支持恢复 |
| 外键无索引 | 高 | 影响关联查询性能 |
| 过多 TEXT 字段 | 低 | 考虑是否真需要 |

### 11.2 性能问题

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| 缺少必要索引 | 高 | 影响查询性能 |
| 联合索引顺序不当 | 中 | 影响查询效率 |
| 未考虑分表 | 高 | 大数据量时性能问题 |
| 频繁 COUNT(*) | 中 | 考虑使用缓存 |

### 11.3 安全问题

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| 敏感数据未加密 | 高 | 密码、身份证等 |
| 缺乏审计字段 | 中 | created_by 等 |
| 权限控制不明确 | 高 | 访问控制设计 |

## 12. 最佳实践提醒

### 数据库设计原则

1. **规范化**：遵循第三范式，减少数据冗余
2. **命名规范**：使用一致且有意义的命名
3. **主键策略**：使用无业务含义的代理键
4. **软删除**：使用 deleted_at 而非物理删除
5. **审计字段**：记录 created_at、updated_at、created_by

### 性能优化原则

1. **索引策略**：为查询创建索引，避免过度索引
2. **字段类型**：选择合适的数据类型，避免浪费
3. **分库分表**：大数据量时考虑水平拆分
4. **查询优化**：避免 SELECT *，使用覆盖索引

### 安全原则

1. **敏感数据**：加密存储敏感信息
2. **访问控制**：在应用层实现权限控制
3. **SQL 注入**：使用参数化查询
4. **审计日志**：记录关键操作
