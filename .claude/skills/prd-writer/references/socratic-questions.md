# 苏格拉底式问题库

按主题分类的提问模板，帮助在对话中深入挖掘需求。

---

## 1. 产品目标类

**核心问题**：用户想解决什么问题？

| 场景 | 提问 |
|------|------|
| 不明确问题 | "你能具体描述一下用户目前遇到的问题吗？" |
| 质疑问题 | "为什么现有的解决方案不够好？" |
| 场景还原 | "请描述一个具体的使用场景，用户当时遇到了什么？" |
| 价值确认 | "解决这个问题对用户来说有多重要？" |
| 痛点深度 | "这个问题给用户带来了什么具体的影响或损失？" |

**追问技巧**：
- 用"然后呢？"继续深入
- 用"具体来说呢？"获取细节
- 用"能举个例子吗？"验证理解

---

## 2. 用户角色类

**核心问题**：谁是目标用户？他们有什么不同？

| 场景 | 提问 |
|------|------|
| 角色确认 | "谁会使用这个产品/功能？" |
| 角色区分 | "这些用户之间有什么不同？" |
| 权限边界 | "不同角色能看到/操作的内容有什么不同？" |
| 场景差异 | "不同角色的使用场景有什么不同？" |
| 价值差异 | "这个功能对不同用户的价值是什么？" |

**追问技巧**：
- 问"为什么"了解深层原因
- 问"如果...会怎样"探索边界

---

## 3. 功能需求类

**核心问题**：用户需要什么功能？

| 场景 | 提问 |
|------|------|
| 功能提取 | "用户完成这个目标需要做哪些操作？" |
| 操作流程 | "用户第一步会做什么？然后呢？" |
| 结果确认 | "用户操作完成后，期望看到什么结果？" |
| 异常处理 | "如果操作失败了，用户会看到什么？" |
| 替代方案 | "如果这个功能不可用，用户会怎么做？" |

**追问策略**：
- 从用户的原始描述中提取关键词
- 不要主动添加用户未提及的功能
- 用"还有呢？"鼓励用户补充

---

## 4. 数据存储类

**核心问题**：需要存储什么数据？

| 场景 | 提问 |
|------|------|
| 数据来源 | "这些数据从哪里来？谁创建？" |
| 数据修改 | "数据创建后会被修改吗？谁可以修改？" |
| 数据删除 | "数据需要删除吗？软删除还是硬删除？" |
| 数据关联 | "这些数据和其他数据有关系吗？" |
| 数据量级 | "预计会有多少数据？需要考虑分库分表吗？" |

**数据库设计追问**：
- "表 A 关联表 B，这个关系是必须的吗？"
- "这个字段设置为必填，用户在什么场景下填写？"
- "这个索引是为了优化什么查询？"
- "为什么选择这种数据类型？考虑了哪些因素？"

---

## 5. 页面交互类

**核心问题**：用户会看到什么、做什么？

| 场景 | 提问 |
|------|------|
| 页面目标 | "用户来这个页面想完成什么任务？" |
| 核心元素 | "页面上最重要的元素是什么？" |
| 操作流程 | "用户在这个页面会做什么操作？" |
| 反馈确认 | "操作完成后，用户期望看到什么反馈？" |
| 页面跳转 | "用户完成操作后会去哪里？" |

**基于设计稿的追问**：
- "这个按钮的作用是什么？点击后会发生什么？"
- "这个区域的布局在不同屏幕尺寸下会变化吗？"
- "这个数据展示的更新频率是怎样的？"
- "这个状态（加载/成功/失败）如何展示？"

---

## 6. 边界确认类

**核心问题**：什么不在范围内？

| 场景 | 提问 |
|------|------|
| 范围确认 | "第一期必须包含哪些功能？" |
| 排除确认 | "哪些功能是明确不在本次范围内的？" |
| 技术约束 | "有什么技术限制或要求需要我知道？" |
| 兼容性 | "需要兼容什么系统/浏览器/设备？" |
| 性能要求 | "对性能有什么具体要求？" |

**追问技巧**：
- 用"如果...就太棒了"探查潜在需求
- 用"未来可能会考虑什么"了解规划但不实现

---

## 7. 优先级类

**核心问题**：什么最重要？

| 场景 | 提问 |
|------|------|
| 优先级确认 | "如果只能做一个，哪个最重要？" |
| 依赖关系 | "这些功能之间有依赖关系吗？" |
| 价值排序 | "用户最常用的功能是哪些？" |
| 风险排序 | "哪些功能的风险最高？" |

---

## 8. 验证类

**核心问题**：我的理解对吗？

| 场景 | 提问 |
|------|------|
| 总结确认 | "让我确认一下，我的理解是...对吗？" |
| 遗漏检查 | "还有我没想到但很重要的方面吗？" |
| 完整性 | "这些信息足够开始写 PRD 了吗？" |
| 优先级确认 | "这些功能的优先级排序对吗？" |

---

## 提问原则

### 要做

1. **开放式提问**：用"什么"、"为什么"、"如何"开头
2. **聚焦当下**：只问用户提到的内容相关的问题
3. **积极倾听**：根据回答调整后续问题
4. **定期总结**：阶段性总结让用户确认

### 不要做

1. **引导性提问**："你觉得需要 XX 功能吗？"（暗示功能）
2. **假设性提问**："如果用户想...就太好了"（添加需求）
3. **过于开放**："还有什么要说的吗？"（用户不知如何回答）
4. **连续追问**：一次只问 1-2 个关键问题

## 对话示例

### 好的示例

```
用户：我想做一个博客系统。

助手：博客系统听起来很有意思。能先了解一下，你做这个博客的目的是什么？

用户：想分享我的技术文章。

助手：明白了，分享技术文章。那你的目标读者是谁呢？是其他开发者还是普通用户？

用户：主要是开发者同行。

助手：了解了，是面向开发者。那对于这个博客系统，你最想实现的核心功能有哪些？
```

### 不好的示例

```
用户：我想做一个博客系统。

助手：好的，我理解。你需要用户注册登录、文章管理、评论系统、
标签分类、搜索功能、后台管理、数据统计、SEO优化、
文章推荐、社交分享等功能对吗？
（错误：主动添加了大量功能）
```
