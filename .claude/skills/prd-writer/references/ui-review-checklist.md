# UI 设计稿审查清单

当用户提供了 UI 设计稿时，使用此清单进行系统性的审查和对话。

---

## 1. 基础信息确认

### 1.1 设计稿来源

| 检查项 | 说明 |
|--------|------|
| 设计工具 | Figma / Sketch / Adobe XD / 其他 |
| 链接 | 提供设计稿访问链接 |
| 版本 | 当前版本号 |
| 标注完成度 | 是否有完整的标注和切图 |

### 1.2 设计规范

| 检查项 | 说明 |
|--------|------|
| 设计系统 | 是否使用了设计系统/组件库 |
| 配色方案 | 主色、辅助色、背景色、文字色 |
| 字号体系 | 标题、正文、注释的字号层级 |
| 间距体系 | 间距、边距的规范值 |
| 圆角/阴影 | 统一的视觉风格 |

---

## 2. 页面级审查

### 2.1 页面完整性

对每个页面回答以下问题：

| 问题 | 检查 |
|------|------|
| 页面目标 | 这个页面的核心目标是什么？ |
| 目标用户 | 谁会访问这个页面？ |
| 关键元素 | 页面最重要的元素是什么？ |
| 操作入口 | 用户在这里可以做什么操作？ |
| 页面出口 | 用户完成操作后去哪里？ |

### 2.2 页面清单模板

| 页面名称 | 路由 | 目标用户 | 核心功能 | 优先级 |
|----------|------|----------|----------|--------|
| [页1] | [路径] | [角色] | [功能] | P0/P1/P2 |

---

## 3. 组件级审查

### 3.1 通用组件

| 组件类型 | 审查要点 |
|----------|----------|
| 按钮 | 何时使用主按钮/次按钮/文字按钮？loading 状态？禁用状态？ |
| 表单 | 必填项标识？错误提示？验证规则？ |
| 卡片 | 何时使用卡片？卡片内元素如何排列？ |
| 列表 | 列表项如何展示？排序方式？分页/加载更多？ |
| 导航 | 主导航在哪里？面包屑？返回路径？ |
| 弹窗 | 何时使用弹窗？弹窗内操作后去向？ |

### 3.2 交互状态

| 状态 | 需要确认的问题 |
|------|----------------|
| 默认状态 | 元素默认显示什么？ |
| 悬停状态 | 鼠标悬停有什么反馈？ |
| 点击状态 | 点击时有什么视觉反馈？ |
| 加载状态 | 加载中如何展示？ |
| 空状态 | 没有数据时显示什么？ |
| 错误状态 | 出错时显示什么？如何恢复？ |
| 成功状态 | 操作成功后显示什么？ |

---

## 4. 响应式设计审查

### 4.1 断点确认

| 断点 | 宽度范围 | 设计差异 |
|------|----------|----------|
| 移动端 | < 768px | 布局如何变化？ |
| 平板端 | 768px - 1024px | 布局如何变化？ |
| 桌面端 | > 1024px | 基准设计 |

### 4.2 审查问题

- "这个布局在不同屏幕宽度下如何适配？"
- "移动端是否有独立的交互设计？"
- "是否需要隐藏某些元素或简化导航？"

---

## 5. 可访问性审查

### 5.1 基础检查

| 检查项 | 问题 |
|--------|------|
| 颜色对比 | 文字和背景的对比度是否足够？ |
| 可点击区域 | 按钮/链接的可点击区域是否足够大？ |
| 焦点状态 | 使用键盘能否导航到所有交互元素？ |
| 图片替代 | 图片是否有有意义的 alt 文本？ |

### 5.2 追问示例

- "这个颜色对比度是否符合 WCAG 标准？"
- "视觉障碍用户如何使用这个页面？"

---

## 6. 交互流程审查

### 6.1 流程图谱

用简单的流程图记录关键交互：

```
[页面A] → [操作] → [页面B] → [操作] → [页面C]
           ↓
        [弹窗/提示]
```

### 6.2 需要确认的问题

| 流程节点 | 确认问题 |
|----------|----------|
| 入口 | 用户从哪里进入这个流程？ |
| 操作 | 每个步骤用户需要做什么？ |
| 反馈 | 操作后用户看到什么反馈？ |
| 验证 | 何时验证？验证失败如何处理？ |
| 出口 | 用户在哪里退出流程？ |
| 中断 | 用户中途退出如何处理？ |

---

## 7. 文案审查

### 7.1 文案一致性

| 检查项 | 问题 |
|--------|------|
| 术语统一 | 是否使用了统一的术语？ |
| 按钮文案 | "确定"vs"提交"vs"保存"是否一致？ |
| 提示文案 | 错误/成功/警告文案风格是否统一？ |
| 文案语气 | 语气是否适合目标用户？ |

### 7.2 追问示例

- "这个按钮上的文案用户能理解吗？"
- "如果用户看到这条提示，他们知道下一步做什么吗？"

---

## 8. 边缘情况处理

### 8.1 常见边缘情况

| 场景 | 确认问题 |
|------|----------|
| 无数据 | 没有数据时页面显示什么？ |
| 数据过多 | 数据量大时如何展示？分页？ |
| 网络错误 | 网络异常如何处理？重试机制？ |
| 权限不足 | 用户没有权限时显示什么？ |
| 页面不存在 | 404 页面如何设计？ |

### 8.2 追问示例

- "如果用户网络断了，会发生什么？"
- "如果用户上传一个很大的文件，会怎样处理？"

## 10. 快速提问清单

当查看设计稿时，依次问自己这些问题：

### 基础理解
1. 这个页面的核心目标是什么？
2. 谁是目标用户？
3. 用户为什么来这个页面？

### 功能确认
4. 用户可以做什么操作？
5. 操作后会发生什么？
6. 如果操作失败呢？

### 视觉确认
7. 最重要的元素是什么？优先级如何？
8. 视觉层次是否清晰？
9. 响应式设计如何处理？

### 完整性
10. 空状态设计了吗？
11. 加载状态设计了吗？
12. 错误状态设计了吗？

---

## 11. 与用户对话模板

### 设计稿审对话示例

```
我已经查看了你的设计稿，有几个问题需要确认：

关于[页面A]：
1. 用户点击这个按钮后，会跳转到新页面还是打开弹窗？
2. 加载数据时，这个区域显示什么？

关于[组件B]：
1. 这个状态（异常/正常/空）分别显示什么内容？
2. 用户可以对这个卡片做什么操作？

关于响应式：
1. 移动端需要隐藏这个区域吗？
2. 平板端布局需要调整吗？

请逐一回答这些问题，帮助我更准确地理解设计意图。
```
